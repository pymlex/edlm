Функциональные требования

UC-1 — Генерация рабочего черновика курса​

АкторыАвтор, LLM service, DB
ПредусловияАвтор залогинен, указаны тема, уровень, длительность
Основной поток1. Автор задаёт параметры. 2. Система валидирует (BR-01, BR-02). 3. Отправляет промпт в LLM. 4. LLM возвращает черновик. 5. Сохраняется v1. 6. Отображается в редакторе.
Постусловия (успех)Черновик сохранён, метаданные (версия, источники, время, токены)
Альтернативные потокиA1: файл > лимита — предупреждение. A2: создание из шаблона — без LLM.
ИсключенияE1: LLM недоступна — ошибка, ретрай.
Бизнес-правилаBR-01: доступ к черновику только автор/модератор. BR-02: проверка лицензии прикреплённых файлов.

UC-2 — Загрузка и привязка материалов автора​

АкторыАвтор, File Service, система прав
Основной поток1. Автор открывает «Материалы» → «Загрузить». 2. Выбирает файлы, указывает тип и права. 3. Проверка размера и формата (BR-03). 4. Сохраняется в File Service, запись в DB. 5. Превью и опция «Включить в генерацию».
ПостусловияФайл привязан к черновику, метаданные записаны
Альтернативные потокиA1: большой файл — предложение загрузить фрагмент. A2: сомнительная лицензия — пометка для модерации.
Бизнес-правилаBR-03: макс. 20 МБ в MVP. BR-04: видео автоматически конвертируется.

UC-3 — Редактирование курса с подсказками LLM​

АкторыАвтор, UI редактора, LLM service, система версий
Основной поток1. Открывает черновик. 2. Правит вручную или запрашивает улучшение. 3. При запросе LLM отправляет контекст. 4. LLM возвращает варианты. 5. Автор принимает вариант или корректирует. 6. Сохраняется новая версия (vN).
ПостусловияНовая версия сохранена, журнал правок обновлён
Альтернативные потокиA1: откат к предыдущей версии. A2: заморозка черновика для совместной работы.
ИсключенияE1: LLM выдал опасный контент — правка не применяется, отправляется на модерацию.
Бизнес-правилаBR-05: все изменения фиксируются с автором и временем, ветвление версий допускается.

UC-4 — Публикация курса и инициирование экспертной рецензии​

АкторыАвтор, рецензент, модерация, сервис уведомлений
Основной поток1. Автор нажимает «Опубликовать». 2. Предпубликационные проверки (BR-07). 3. Курс становится видимым (сразу или после модерации). 4. При ручной проверке назначаются рецензенты. 5. Рецензенты оценивают, пишут обязательные правки. 6. Автор вносит правки, курс публикуется.
ПостусловияКурс опубликован, рецензии сохранены
Альтернативные потокиA1: мгновенная публикация с пометкой «experimental». A2: minor/major правки.
ИсключенияE1: нарушение авторских прав — курс снимается.
Бизнес-правилаBR-07: чувствительные темы — обязательная ручная модерация. BR-08: рецензия должна содержать оценку 1–5, текст, признак обязательных правок.

UC-5 — Поиск курса​

АкторыПользователь, Search Service
Основной поток1. Вводит запрос и/или фильтры. 2. Отправляет в Search Service. 3. Возвращается релевантный список. 4. Отображаются превью. 5. Выбирает курс.
ПостусловияСписок отфильтрован, переход на страницу курса
Альтернативные потокиA1: фильтр «только бесплатные». A2: анонимный пользователь — сокращённая карточка.
ИсключенияE1: Search Service недоступен — кешированная выдача.
Бизнес-правилаBR-10: скрывать черновики/отозванные. BR-11: персонализированная сортировка только для залогиненных.

UC-6 — Запись пользователя на курс​

АкторыПользователь, Course Service, Payment Service, Notification Service
Основной поток1. Нажимает «Записаться». 2. Если бесплатный — создаётся запись, курс в «Мои курсы». 3. Если платный — инициируется оплата; после успеха создаётся запись. 4. Уведомление.
ПостусловияПользователь записан, доступ открыт
Альтернативные потокиA1: корпоративный аккаунт — автоматическая запись по лицензии.
ИсключенияE1: Payment Service недоступен — транзакция откладывается.
Бизнес-правилаBR-09: доступ к корпоративным метрикам по соглашению. BR-12: один пользователь не может записаться на курс повторно. BR-13: запись подтверждается только после успешной оплаты.
